# Design decisions

Comments, tests and the other documents in this repository cite design decisions by a short id
(`D-1`, `D-7`, ...). The ids come from the original design specification for the EVM port, which is
not published. This page states each decision that the code relies on, in one place, so that every
citation resolves. Ids that the code never cites are omitted, which is why the numbering has gaps.

| Id | Decision | Where it shows up |
|---|---|---|
| **D-1** | The three contracts are **upgradeable UUPS proxies**, with no timelock and no pending-implementation slot. *Amended by D-17:* the upgrade authority is `X402Config.owner()`, not `X402Config.admin`; the other two contracts read `CONFIG.owner()` live. Chosen as a revision, replacing an earlier immutable design, for parity with the Solana program's upgrade authority (which is likewise a separate key from the Solana admin). | `src/X402Config.sol`, `test/Upgrade.t.sol`, `test/X402Config.owner.t.sol`, `docs/risk-register.md` §4 and §5 |
| **D-2** | `X402Escrow` reads `X402Stake.bondedOf(provider)` as a `view`, in one direction only. `X402Stake` holds no reference back to the escrow. | `src/X402Escrow.sol`, `src/interfaces/IX402StakeView.sol` |
| **D-3** | `X402Config` is read by both other contracts and **written by neither**. Counters that the Anchor program keeps on its config account (the four stake accounting totals, the per-verifier daily-cap counter) live on `X402Stake`, next to the custody they count. | `src/X402Stake.sol`, `docs/divergences.md` rows 7 and 8 |
| **D-4** | The `Escrow` struct is packed into **four** storage slots (128 bytes). `script/check-layout.sh` fails if it is anything else. | `src/Types.sol`, `script/check-layout.sh` |
| **D-6** | *Superseded by D-17.* The admin was a single key changed through `updateConfig` in one step, and a mistyped `newAdmin` could not be recovered. Now the OWNER appoints the admin (`setAdmin`), the owner is the recovery path for a wrong admin, and `updateConfig` refuses any non-zero `newAdmin` (`AdminChangeRequiresOwner`); the argument stays only for ABI stability. | `src/X402Config.sol`, `docs/deploy-runbook.md` §6.3 |
| **D-7** | Storage layouts are **append-only**. An append is an upgrade; a change that cannot be expressed as an append is a redeploy behind a new proxy. The proxy, not the implementation, carries the CREATE2 salt. | `script/check-layout.sh`, `script/check-layout.py`, `script/Deploy.s.sol` |
| **D-9** | A buyer's voucher `seq` is a high-water mark and never goes backwards. | `src/X402Escrow.sol` |
| **D-10** | `redeemVoucher` is restricted to the redeemer role (`onlyRedeemer`), matching the Anchor program's `redeem_voucher`. A permissionless fallback was specified with a delay of 1 h to 7 d and **not built**: a voucher is redeemable for at most 2,220 s, so such a fallback could never fire. A redesign is pending (risk register §15). The redeemer key is distinct from the backend relayer key, which has no on-chain role. | `src/X402Escrow.sol` |
| **D-11** | *Superseded by D-18.* Gasless deposits went through **Permit2**; nothing used that door, and D-18 removed `depositWithPermit2`. The `PERMIT2` storage slot stays (append-only layout), read by nothing. A buyer funds with `approve` + `depositFor`. | `src/X402Escrow.sol`, `docs/chain-facts.md` |
| **D-13** | The **boundary table**: where two time windows meet, exactly one of them owns the shared instant. Every row is tested at `-1`, exact and `+1`. | `test/Boundaries.t.sol` |
| **D-14** | The **four accounting identities** (for example: the sum of escrow balances equals `totalEscrowed`). Solvency is defined by internal accounting, never by `balanceOf`. | `test/invariant/Invariants.t.sol` |
| **D-15** | `withdraw()` takes no destination argument and pays `msg.sender`; `withdrawStake` has the same shape. | `src/X402Escrow.sol`, `src/X402Stake.sol`, `docs/divergences.md` |
| **D-16** | **Agent payment delegation (x402-aligned).** A voucher is authorised by exactly one of: (a) an ECDSA signature by `payer`; (b) an ECDSA signature by a DELEGATE key the payer authorised on chain (`authorizeDelegate` / `authorizeDelegateBySig`), not revoked and not past `validUntil`, within the delegate's own per-voucher and rolling-window caps — which can only narrow the escrow's, and the escrow's still apply. *Amended by D-18:* the third branch, a payer's EIP-1271 `isValidSignature`, was removed. A contract-wallet payer calls `authorizeDelegate` directly and lets a delegate sign. A delegate signs vouchers and nothing else. Every delegation write, direct or relayed, consumes the shared `authNonce`. ERC-6492 is not accepted. Storage: two mappings appended before `__gap` (50 → 48). | `src/X402Escrow.sol` (`_voucherAuthority`, `_authorizeDelegate`, `_revokeDelegate`), `test/X402Escrow.delegate.t.sol` |

| **D-17** | **Two roles in `X402Config`: OWNER and ADMIN.** The OWNER (OpenZeppelin `Ownable2StepUpgradeable` v5.1.0, ERC-7201 storage, so no sequential slot) is kept cold, on a Ledger or a Safe. It is the UUPS upgrade authority of all three contracts and appoints the admin (`setAdmin`). It moves in two steps (`transferOwnership`, then `acceptOwnership` by the incoming key) and can never be renounced (`renounceOwnership` always reverts) or become `address(0)`. **No role holds a door that transfers a token to itself; the owner's power over funds is the upgrade.** That does not make the admin harmless to funds: through parameters alone it can register a verifier and raise the slash parameters, allowing it to take provider stake within the caps to a beneficiary it picks — since D-19 it also sets the arbiter and can cut the delay to 10 minutes, so it needs no other key; **accepted by the owner on 2026-10-14** because the admin wallet is held as securely as the owner wallet (`docs/risk-register.md` §4a), and it can repoint the treasury and raise the take rate to 30% with no delay. Alert on `ConfigUpdated` and `VerifierRegistered` (`docs/risk-register.md` §4a). The ADMIN is operational: `updateConfig`, `setPaused`, the verifier registry and `cancelSlash`, every value bounded by `_validate`. It cannot upgrade or appoint. The deployer holds no role after deploy (`Deploy.s.sol` refuses otherwise). Migration: `initializeV2()` (`reinitializer(2)`, no arguments) runs inside the upgrade's `upgradeToAndCall` and sets owner = the current admin. Initializer versions after it: Config 2, Stake 1, Escrow 1 — the next Config reinitializer must be `reinitializer(3)`, the next Stake or Escrow one `reinitializer(2)`. Ownership then moves to the cold key in two steps. Also in D-17: the **seq jump cap**, a redeemed voucher needs `seq <= seqHigh + MAX_SEQ_GAP` (constant 1,000,000, `VoucherSeqGapTooLarge`), on every path and for every signer kind. | `src/X402Config.sol`, `src/X402Escrow.sol`, `script/UpgradeOwnerSplit.s.sol`, `script/UpgradeByOwner.s.sol`, `test/X402Config.owner.t.sol`, `test/X402Escrow.seqcap.t.sol`, `test/NoTokenDoors.t.sol` |
| **D-18** | **Smaller attack surface, same storage.** (1) EIP-1271 is removed from voucher redemption: no payer-chosen code runs in the money path. (2) **Every payer decision consumes `authNonce`**: the direct `setLimits` and `requestWithdraw` now do too, as the delegation doors already did, so a withheld relayed signature can never land after a later decision. (3) A relayed authorisation's `deadline` may be at most `MAX_SIGNATURE_LIFETIME_SECONDS` (3,600 s) past the block that lands it (`SignatureDeadlineTooFar`). This bounds how far ahead of now a deadline may be when the call lands — how early before its deadline a signature can land — and is not a signature lifetime: a far-deadline signature still lands in its last hour. What kills a withheld signature is the shared `authNonce` of (2). (4) The unused Permit2 deposit door is removed. (5) Dead surface is removed: the `recoverVoucherSigner` and `verifierExpiry` views, five errors with no producer, and the one-line `narrow` forwarders. Solana-parity notes that described removed code moved to `docs/divergences.md`. | `src/X402Escrow.sol`, `src/X402Config.sol`, `src/Errors.sol`, `test/X402Escrow.authnonce.t.sol`, `test/X402Escrow.delegate.t.sol` |
| **D-19** | **The dispute upgrade: a dispute step, an ARBITER, a blocklist, pause on the exits, a settable slash delay.** (1) `X402Stake.disputeSlash(requestId)`: the record's provider, `Pending`, `block.timestamp < executableAt`, never paused or blocked → `Disputed` (appended to `SlashStatus`), `disputedAt` (appended to `SlashRecord`), reservation kept; `executeSlash` refuses it. (2) `X402Config.arbiter` (`setArbiter`, admin; `address(0)` = none), a person's wallet or a Safe, never the backend: `upholdSlash` (`Disputed → Pending`, `executableAt = max(frozen, now)`, only before `disputedAt + DISPUTE_TIMEOUT_SECONDS` (`DisputeTimedOut`), (the per-record `ArbiterIsVerifier` check was removed in audit F R5: Config keeps the arbiter off every live verifier); one dispute per record, `AlreadyDisputed`; `setArbiter` refuses the admin and any live verifier, `InvalidArbiter`), `cancelSlash` beside the admin on `Pending` or `Disputed`, and `setBlocked(a, true)` only. (3) `expireSlash` releases a `Disputed` record after `disputedAt + DISPUTE_TIMEOUT_SECONDS` (30 d, `CancelReason.DisputeUnresolved`) or when the verifier cannot sign; the grace period no longer applies to it. (4) `X402Config.setBlocked` / `blocked` and `assertActive(a, b, c)` — one Config call per guarded door, `ProgramPaused` then `AddressBlocked`. (5) Pause now closes the owner exits too (divergences row 28). (4b) **Role separation**, in one helper `_assertRolesDistinct()` run at the end of `setAdmin`, `setArbiter`, `registerVerifier` and `updateConfig` (audit F R5): the admin is not a live verifier (`InvalidAdmin`); the arbiter is not the admin, the redeemer or a live verifier (`InvalidArbiter`); `setArbiter(0)` is refused. Held by audit D's system invariants (`test/invariant/audit-d/`). (4c) **All or wait** (D-20): `executeSlash` pays the whole reservation only when it fits both windows, otherwise `SlashWindowNotDrained`; no partial payment. (4d) `updateConfig` refuses `penaltyAmount > verifierDailyCap` and a `minimumStake` whose cap allowance rounds to 0. A stolen admin alone can take stake within the caps: accepted (risk register §4a). (5b) `disputeSlashBatch` / `upholdSlashBatch` / `cancelSlashBatch(bytes32[])`: atomic like `redeemVoucherBatch`, loop the single call's own internal function (`_dispute`, `_uphold`, `_release`), caller checked once, `EmptyBatch` / `BatchTooLarge` above `MAX_SLASH_BATCH` (64). (6) `setSlashDelay` (admin, fixed bounds `[MIN_SLASH_DELAY_SECONDS, MAX_SLASH_DELAY_SECONDS]` = 10 min to 22 d; the earlier coupling to `unbondingPeriodSeconds` was removed in audit F R3, because a proposed penalty is held by `pendingSlash` whatever the delay), stored in Config's appended slot rather than in `ParamSet`, because `ParamSet`'s three slots are full and `_params` sits above `verifiers`: a fourth slot would shift live state. Reads `SLASH_DELAY_SECONDS` while unset, so the upgraded proxy keeps 72 h with no initializer. **Upgrade order: Config, then Stake and Escrow** — the new Stake and Escrow call `assertActive`, `slashDelaySeconds` and `arbiter`. Initializer versions are unchanged (Config 2, Stake 1, Escrow 1). | `src/X402Config.sol`, `src/X402Stake.sol`, `src/X402Escrow.sol`, `script/UpgradeByOwner.s.sol`, `test/X402Stake.dispute.t.sol`, `test/X402Config.arbiter.t.sol`, `test/AddressBlocklist.t.sol`, `test/Pause.t.sol`, `test/Upgrade.dispute.t.sol` |
| **D-20** | **Simplification (audit F).** R1: one `_deadline(rec)` in X402Stake (Disputed → `disputedAt + 30 d`, else `executableAt + 7 d`) used by `executeSlash`, `upholdSlash` and `expireSlash`. R2: the unreachable defensive branches on the slash money path are gone and the subtractions that relied on `reserved <= pendingSlash <= atRisk` are CHECKED, so a broken invariant reverts instead of clamping (the execute-side `NothingToSlash`, the `atRisk` clamp and the dead "smaller stake" leg of the write-off rule). R3: the slash delay has fixed bounds (10 min to 22 d), no coupling to unbonding; `MIN_UNBONDING_PERIOD_SECONDS` (11 d) still covers breach-to-proposal. R5: one `_assertRolesDistinct()`; errors `ArbiterIsVerifier`, `VerifierIsAdminOrArbiter`, `RedeemerIsArbiter` removed. R4 (owner decision): pure all or wait — no partial payment and no last-day exception, `applied == reserved` for every executed record (`invariant_everyExecutedRecordWasPaidInFull`), `VerifierDailyCapExceeded` folded into `SlashWindowNotDrained`. Audit G G-1: `_validate` requires `verifierDailyCap >= 2 * penaltyAmount`; review 2026-10-15 R-1 adds the provider-day twin, `minimumStake * slashCapBps / 10_000 >= 2 * penaltyAmount` (`InvalidMinimumStake`, replacing the C7 rounds-to-0 check), so a provider at the minimum fits two maximal records a day and one small execution cannot starve a full-cap record until it expires. R7: `slashProviderBps()` removed; the redeem entry points' duplicate pause check removed (`_redeem`'s `assertActive` checks it). | `src/X402Stake.sol`, `src/X402Config.sol`, `src/X402Escrow.sol`, `test/X402Stake.audit.t.sol` |
| **D-21** | **Signed means collectable: a payer's tightening waits out `TIGHTEN_DELAY_SECONDS`.** (Design "no platform debt" §3.1, step 5; closes business finding 7 and review H1.) `TIGHTEN_DELAY_SECONDS = WITHDRAW_DELAY_SECONDS` (3,600 s > 2,220 s, the longest a voucher lives). (1) Lowering either stored cap — `setLimits`/`setLimitsBySig`, or a re-grant of a delegate that can still sign — stores the caps in force before the call in a `PriorCaps {maxVoucherAmount, maxPerWindow, until}` hold (`priorEscrowCaps[payer]`, `priorDelegateCaps[payer][delegate]`), `until = now + 3,600` for the escrow and `until = min(now + 3,600, validUntil before the change)` for a delegate (review 2026-10-16 F1/F4: a hold never outlives the grant it protects). While `now <= until`, `_redeem` accepts a voucher that fits the stored pair OR the held pair, each pair checked WHOLE, never field by field (F3; `_heldRefusal`); the hold is read only when the stored pair refuses. A pure raise applies at once and leaves the hold alone. A lowering while a hold runs merges the two pairs field by field into the one slot (residual: risk register §14b). (2) `revokeDelegate` still sets `revoked` and unlists at once, and writes the hold too: a revoked grant still signs until `hold.until` (and never past its `validUntil`). Revoking a grant that has already lapsed writes no hold. A grant revoked before this upgrade has `until == 0` and stays dead. (3) Every grant needs `validUntil >= now + 3,600` (`DelegateValidUntilInvalid`), so a shortened horizon also waits out the delay. (4) View `effectiveCapsOf(payer, delegate)`: the per-field ENVELOPE of what `_redeem` accepts now (a necessary bound for prevalidation, not a sufficient one), delegate caps 0 when the grant cannot sign. (5) Event `CapsHeld(address indexed payer, address indexed delegate, uint64 maxVoucherAmount, uint64 maxPerWindow, uint64 until)` on every hold write (`delegate = address(0)` for the escrow's caps; for a revoked grant `until` is the end of its grace; a later one for the same pair of keys replaces it) — F6. Structs, errors and the EIP-712 types are unchanged; two mappings appended, `__gap` 48 → 46. With the exit delay (D-1 parity, 3,600 s), no payer call can make an admitted voucher unredeemable before its deadline, or withdraw the money it needs. The cost: a stolen delegate key PLUS the redeemer key can spend for up to one more hour within the old caps. Initializer versions unchanged (Escrow 1); no initializer runs. | `src/X402Escrow.sol`, `src/Constants.sol`, `test/X402Escrow.tighten.t.sol`, `test/Upgrade.tighten.t.sol`, `test/helpers/legacy/X402EscrowPreTighten.sol` |
